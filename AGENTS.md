# AGENTS

Purpose: Quick orientation for anyone editing the project. Keep this file current as routes/auth/config change.

## Project snapshot (2025-12-04)
- Next.js 16 App Router with Supabase SSR auth and Tailwind 4 inline theming (`src/app/globals.css`); global `html`/`body` overflow is locked so the browser viewport itself never shows a scrollbar, and any necessary overflow should live inside intentional in-app scroll regions.
- Protected routing enforced in `proxy.ts`; `/login`, `/auth/login`, `/auth/callback`, and the exact `/terms`, `/privacy`, `/cookies`, `/notification-terms`, and `/sms-terms` policy paths are public app pages. Policy pages bypass Auth lookups and scroll internally; their links appear on login, Settings/phone entry, every notification prompt, and the account menu. `/api/*` handles its own authorization; `/api/telnyx/voice/fallback` returns static hang-up XML on GET/POST without accessing participant data or placing calls.
- `/` lists public active studies after unanswered notification preferences, the demographic survey, and required profile completion. A study is listed when `is_private = false` and the current time falls within its inclusive date window (null bounds are open-ended). Each card shows `Study {id}` with its start and end date/time in the user's device timezone beneath it (or `No start date` / `No end date` for open bounds), links to `/study/{id}`, and loads captions only after selection. The list scrolls internally with space reserved for the account controls; an empty result shows `No active studies`, and query failures show a separate load error.
- The caption viewing experience at `/study/{studyId}` opens on a dedicated welcome/start page before the first caption with a `Start Study` button (`Continue Study` for an existing participation), allows returning to that start page by navigating backward from the first caption, places caption text above the image, and for image captions now shows an Instagram-style action row beneath the image with a heart on the left. Heart votes save as `funny` in `study_caption_vote_events` and `1` in `caption_votes`, do not auto-advance to the next caption, can be removed by clicking the filled heart again, support double-tap toggling on the image or caption text, and captions remain in the study feed after they are liked, with the persisted like state rehydrated on reload. The study screen shows a bottom-center `current/total` caption progress readout while a caption is visible, support page-wide vertical touch swipes plus page-wide trackpad/mouse-wheel navigation that follows the browser/OS scroll direction setting, show a temporary loading overlay for wheel-driven advances until the wheel gesture goes idle, animate caption changes with a vertical 3D flip when the study advances backward or forward, and support `ArrowUp` / `ArrowDown` keyboard navigation between captions. Each study page SSRs only an initial batch of its active captions and lazily loads more as the user nears the end of the queue instead of blocking first paint on the full active-study corpus; it records `study_caption_vote_events.time_to_vote_ms` for time-to-like, and separately records `study_caption_navigation_events.time_to_next_caption_ms` for time-to-next-caption.
- A new study run shuffles the full deduplicated caption ID list before loading content and pins that order plus the current caption cursor in `study_participations`. Reopening an in-progress study resumes at the last displayed caption in the same order; forward/back navigation checkpoints the cursor, including across lazy-loaded batches. Caption details still load incrementally.
- Caption images use responsive thumbnails only on `images.crackd.ai` and `images.almostcrackd.ai`; external images display and preload their original URLs unchanged. Failed hosted thumbnails retry the original image, including during preloading and when a failure occurs before hydration.
- Study participation persists in `study_participations` with one row per `(profile_id, study_id)`, database-owned `started_at` / `ended_at` timestamps, and a participant-scoped caption-order/cursor checkpoint. `Start Study` (or a forward gesture outside the welcome card) saves before showing captions. The last page after the final caption shows only an End Study step; stats remain hidden until End Study succeeds. Ending atomically saves the current run's counts and median timings in `completion_stats` with the end time. The shared Study Stats screen renders this immutable snapshot immediately and on every completed-study revisit, including after the study expires, without loading captions. Legacy completions without snapshots show a stats-unavailable message instead of fabricated values. Back navigation does not end participation. Home shows `In progress` for start-only rows and `Completed` only when both timestamps exist. Repeated actions preserve original timestamps and stats; writes use the user's JWT through RLS-protected invoker functions. An in-progress study can still be ended if it expires while the final page is open.
- `/study/{studyId}` is a numeric-only study route that shows only captions mapped to that study ID, intentionally ignores `studies.is_private` for direct access, still enforces the nullable active date window for unfinished studies, and shows `sorry, this study is expired!` when an unfinished study exists outside that date window. Completed studies open their saved stats even after expiration. Slug routes are not supported. Superadmins see a tiny bottom-left `which study am I?` bubble that can be clicked to reveal `study {id} | {slug}` for the current study route. The root study list does not show this bubble.
- `/demographics` is a protected survey flow for pending demographic questions. The OAuth callback and home page check for missing demographic answers independently of study availability and redirect here when needed; these checks fail open if the demographic tables cannot be queried. Questions and answer choices are loaded from `demographic_questions`, `demographic_answers`, and non-deleted `demographic_answer_question_mapping` rows; user results save to `demographic_user_responses`. The page loads the pending question queue once, lets the survey card naturally resize for normal questions, switches to searchable internal answer scrolling only when a question has more than 10 answer options, advances between questions immediately after an answer click, shows a brief in-flow fading previous-arrow rollback affordance for only the latest answer, commits older pending answers as soon as they are no longer undoable, flushes pending answers before final skip/redirect, and shows only the pending question count remaining. Skipped question IDs are stored in a user-scoped `demographic_skips` session cookie so returning home does not reopen skipped questions; successful OAuth login clears the cookie so unanswered skipped questions reappear.
- `src/app/page.tsx` checks the Supabase user server-side; redirects to `/login` if missing; checks pending demographics before loading studies; then enforces `profiles.first_name` + `last_name` via a required form before the active-study list or the no-studies message (no longer gates on `is_in_study`). Sign-out uses the shared `signOut` server action.
- The shared account menu includes a `Settings` link immediately above `Sign out`. Protected `/settings` loads the signed-in profile's names and new-study notification preferences, lets the user save both names and all three independent channels together, and preserves edited fields on validation/save errors. Saves use the user's JWT and authenticated profile ID, report success only after an updated row is returned, and refresh profile data shown around the app. The settings form and account menu scroll internally on small viewports.
- Settings also lets the signed-in user enter a country-coded phone number and verify its six-digit code using Supabase's authenticated phone-change flow. Confirmation targets the pending number from `auth.getUser()`, preserves the previous verified number until confirmation, and does not automatically opt into notifications. Telnyx delivers codes through a private database Auth hook after provider activation.
- Email, text, and automated phone reminders use independent preferences and daily noon Eastern scheduling. Texts/calls require an Auth-verified phone number. Production email and phone-call scheduling are enabled; SMS reminders/verification remain pending Telnyx SMS activation. The provider's current voice profile allows US/Canada destinations. No participant was called during setup.
- Protected `/notification-preferences` asks about only NULL email, text-message, and phone-call preferences, one channel at a time. Yes saves TRUE, No saves FALSE, and Skip preserves NULL with a user-scoped HttpOnly session cookie. Successful OAuth login clears notification skips and opens this prompt before demographics, retaining the original destination. Home independently checks unanswered choices; completing/skipping them continues demographics before the destination. Reads fail open if the profile cannot be queried. Authenticated writes only update a still-NULL channel, so stale prompts cannot overwrite choices saved elsewhere. Settings offers Yes, No, and Not answered and preserves NULL when saving unrelated names.
- `src/app/login/page.tsx` posts to `/auth/login` with an unchecked required confirmation of age 18+, U.S. location, and the Terms of Use. The handler rejects missing/forged/duplicate confirmation before contacting Auth, builds a clean `/auth/callback` redirect (no query string), and stores `next` in a cookie so Supabase callback URLs exactly match the allowlist. This self-attestation is separate from research consent and notification opt-ins; there is no stored versioned site-term acceptance or IRB-consent flow. See `docs/site-policy-review.md` for approved research information still needed.
- `src/app/auth/callback/route.ts` exchanges the Supabase code and redirects to the requested `next` path using `NEXT_PUBLIC_SITE_URL` as the preferred deployed origin.
- Supabase helpers: `src/lib/supabase/server.ts` for SSR cookies (guards cookie writes; `await createClient()` server-side) and `src/lib/supabase/client.ts` for browser usage.
- Layout/fonts: `src/app/layout.tsx` registers Geist fonts. `next.config.ts` uses the default `.next` output, with `.next-settings-preview` selected only when the controlled settings preview sets `FUNNYSTUDY_SETTINGS_PREVIEW=1`.
- Interaction feedback: `InteractionFeedback` adds a gentle press/release animation to buttons and links for pointer and keyboard activation. Global CSS provides held-press and focus feedback; account/theme menus animate open. `SubmitButton` shows the active server action's progress label and spinner while disabling sibling submissions (give each button its own `formAction` in multi-action forms). `GoogleSignInForm` keeps the native OAuth POST and provides pending feedback that resets when returning via browser Back. These animations run regardless of `prefers-reduced-motion`.
- Admin area and `/api/admin/*` routes have been removed.

## Setup and commands
- Use Node.js 24.x and npm 11.x for local development and build (`.nvmrc` is set to `24`; `package.json` engines require Node `>=24 <25` and npm `>=11 <12`).
- Required env vars in `.env.local`: `NEXT_PUBLIC_SUPABASE_URL`, either `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` or `NEXT_PUBLIC_SUPABASE_ANON_KEY`, and `NEXT_PUBLIC_GOOGLE_CLIENT_ID`; `NEXT_PUBLIC_SITE_URL` sets the callback and post-login redirect origin (default `http://localhost:3000` if unset).
- Google OAuth redirect must include `http://localhost:3000/auth/callback`.
- Install/run: `npm install`, `npm run dev`; lint: `npm run lint`; build: `npm run build`.
- Demographic, study-selection, participation, and resume-progress regression checks: `npm run test:demographics` (controlled auth/data, no live database required; covers active windows, selection links, completion badges, checkpoint order/cursor restore, lazy resume batching, participation actions, study scope, empty results, and loading errors).
- Caption image regression checks: `npm run test:images` (thumbnail host restrictions, external URL preservation, and responsive caption markup; no live database required).
- Settings regression checks: `npm run test:settings` (browser/server/proxy session isolation and local logout through the real Supabase SDK with mocked HTTP, authenticated reads/writes, names, independent Yes/No/NULL choices, notification prompts/skips, stale writes, validation, reloads, errors, and menu ordering). `npm run preview:settings` starts a loopback-only Next.js preview at `http://127.0.0.1:3014` against an in-memory Supabase fixture; open `http://127.0.0.1:3015/sign-in` to test the complete form flow without touching a live account or database. Its `/reset-notification-preferences` fixture endpoint resets only in-memory choices; opening the app's home route then exercises the prompt.
- Daily study reminders use private database cron functions and Supabase Vault. Administrative rollout, pause/rotation commands, and rollback-only verification are in `docs/daily-study-emails.md`; `npm run study-email -- status production` reports non-sensitive configuration/counts. The setup CLI requires an operator's `SUPABASE_ACCESS_TOKEN` and `RESEND_API_KEY`; neither is needed by Next.js at runtime or exposed publicly.
- SMS setup and verification are documented in `docs/daily-study-sms.md`; `npm run study-sms -- status production` reports configuration/counts without secrets or recipient numbers. Setup uses `TELNYX_API_KEY`, `TELNYX_FROM_NUMBER`, and `TELNYX_MESSAGING_PROFILE_ID` plus the operator's Management API token; Next.js needs no Telnyx credential.

## Authentication sessions
- Auth cookies are scoped to this app and Supabase project using `getSupabaseAuthCookieOptions`; browser, server, and proxy clients must use the same options.
- Ordinary logout and auth cleanup use `signOut({ scope: "local" })` so other apps remain signed in.
- Existing shared auth cookies are not imported; users sign in once per app after this change.

## Conventions and reminders
- Use the shared Supabase client helpers (`createClient`) for server/client contexts instead of instantiating ad hoc.
- Update the public route allowlist in `proxy.ts` whenever adding unauthenticated pages.
- Tailwind v4 uses CSS-driven tokens; add design tokens in `src/app/globals.css` rather than a config file.
- Do not crop caption images—render them fully (object-contain) and adjust layout instead of cutting off any part of the image.
- COMMANDMENT: Caption text now sits above its image; keep that order consistent and do not let buttons or overlays interrupt it.
- COMMANDMENT: Never let UI overlap—avoid stacking divs so badges, buttons, or bars cover image or caption.
- COMMANDMENT: Before finishing work, run `npm run build` and resolve build errors.
- Keep this doc updated when adding routes, changing auth flow, or adjusting environment requirements.
